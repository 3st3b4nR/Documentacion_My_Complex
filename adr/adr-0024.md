# publicar mycomplex con un dominio seguro

* Estado: propuesto
* Decidentes: Jaider Sebastián Lucuara Cortés - John Esteban Roldán Marín
* Fecha: 2026-09-22

## Contexto y planteamiento del problema

Los usuarios deben poder ingresar a MyComplex mediante direcciones fáciles de reconocer y con una conexión protegida, por ejemplo `app.mycomplex.com`. Se debe definir cómo administrar los dominios y los certificados que permiten usar HTTPS sin depender de renovaciones manuales realizadas por el equipo.

## Impulsores de decisión

* Utilizar direcciones claras y estables para la aplicación y la API.
* Proteger la información enviada entre el usuario y MyComplex mediante HTTPS.
* Evitar que un certificado vencido deje la plataforma inaccesible o genere alertas de seguridad.
* Integrarse con la infraestructura seleccionada para publicar y proteger la aplicación.

## Opciones consideradas

* Azure DNS con certificados administrados por Azure
* Cloudflare DNS y TLS
* Nginx con certificados Let's Encrypt administrados por el equipo

## Resultado de la decisión

Opción elegida: **"Azure DNS con certificados administrados por Azure"**, porque permite administrar los dominios de MyComplex y utilizar certificados que pueden renovarse automáticamente desde los servicios de Azure. Esto disminuye tareas manuales, mantiene la conexión cifrada y evita agregar otro proveedor para una función que Azure ya puede cubrir.

### Consecuencias positivas

* Los usuarios podrán acceder mediante dominios claros y estables.
* La información enviada por Internet se protegerá mediante HTTPS.
* Se reduce el riesgo de que los certificados expiren por olvido.
* La solución se integra con la protección WAF y la plataforma de contenedores.

### Consecuencias negativas

* Aumenta la dependencia de Azure para publicar la aplicación.
* Se requiere una configuración inicial correcta de dominios y certificados.
* Cambiar de proveedor en el futuro implicaría migrar parte de esta configuración.

## Pros y contras de las opciones

### Azure DNS con certificados administrados por Azure

Servicios de Azure para administrar dominios y proteger conexiones HTTPS.

* Bien, porque reduce las renovaciones manuales de certificados.
* Bien, porque se integra con Front Door y Container Apps.
* Bien, porque mantiene esta parte de la infraestructura en el mismo proveedor.
* Malo, porque aumenta la dependencia de Azure.

### Cloudflare DNS y TLS

Servicio externo para administrar dominios y conexiones seguras.

* Bien, porque es una plataforma madura y fácil de administrar.
* Bien, porque puede utilizarse independientemente del proveedor donde se aloje el backend.
* Malo, porque agrega un proveedor adicional.
* Malo, porque parte de sus funciones se superponen con Azure Front Door.

### Nginx con certificados Let's Encrypt administrados por el equipo

El equipo configura directamente el servidor y las renovaciones de certificados.

* Bien, porque ofrece control completo y permite utilizar certificados gratuitos.
* Bien, porque no depende de un servicio específico de nube.
* Malo, porque el equipo debe mantener servidores y renovaciones.
* Malo, porque un error o una renovación fallida puede afectar el acceso a la plataforma.
