# alojar postgresql como servicio administrado

* Estado: propuesto
* Decidentes: Jaider Sebastián Lucuara Cortés - John Esteban Roldán Marín
* Fecha: 2026-09-22

## Contexto y planteamiento del problema

MyComplex ya definió PostgreSQL como su base de datos principal, pero todavía debe decidirse cómo se ejecutará en producción. El equipo necesita una opción que reduzca tareas como instalación, actualizaciones, copias de seguridad y mantenimiento del servidor de base de datos.

## Impulsores de decisión

* Mantener PostgreSQL disponible y actualizado sin administrar un servidor manualmente.
* Reducir el trabajo operativo del equipo.
* Contar con opciones de respaldo y recuperación integradas.
* Mantener una solución que pueda crecer junto con MyComplex.

## Opciones consideradas

* Azure Database for PostgreSQL Flexible Server
* PostgreSQL instalado en una máquina virtual
* PostgreSQL ejecutado en un contenedor administrado por el equipo

## Resultado de la decisión

Opción elegida: **"Azure Database for PostgreSQL Flexible Server"**, porque permite utilizar PostgreSQL sin que el equipo tenga que administrar directamente el servidor donde se ejecuta. El servicio se encarga de gran parte de las tareas de mantenimiento y ofrece funciones de respaldo, recuperación y seguridad que reducen el riesgo operativo del proyecto.

### Consecuencias positivas

* El equipo dedica menos tiempo a mantener el servidor de base de datos.
* Se cuenta con mecanismos administrados de respaldo y recuperación.
* Se facilita aumentar los recursos de la base de datos cuando el sistema crezca.
* Se integra con la red y los servicios de seguridad de Azure.

### Consecuencias negativas

* Tiene un costo mensual mayor que ejecutar PostgreSQL en infraestructura mínima propia.
* Se depende de Azure para la operación de la base de datos.
* Algunas configuraciones de bajo nivel estarán limitadas frente a una instalación completamente propia.

## Pros y contras de las opciones

### Azure Database for PostgreSQL Flexible Server

Servicio administrado que permite utilizar PostgreSQL sin mantener directamente el servidor.

* Bien, porque reduce las tareas de instalación, actualización y mantenimiento.
* Bien, porque incluye opciones de respaldo, recuperación y disponibilidad.
* Bien, porque se integra con los demás servicios Azure de MyComplex.
* Malo, porque tiene un costo recurrente.
* Malo, porque aumenta la dependencia del proveedor cloud.

### PostgreSQL instalado en una máquina virtual

El equipo instala y administra PostgreSQL directamente sobre un servidor virtual.

* Bien, porque ofrece control completo sobre la configuración.
* Bien, porque permite decidir exactamente cómo se instala y actualiza PostgreSQL.
* Malo, porque el equipo debe encargarse de actualizaciones, copias, seguridad y recuperación.
* Malo, porque un error de administración puede afectar directamente los datos del sistema.

### PostgreSQL ejecutado en un contenedor administrado por el equipo

La base de datos se ejecuta en un contenedor similar al utilizado para el backend.

* Bien, porque simplifica ambientes locales y de pruebas.
* Bien, porque permite repetir la configuración fácilmente.
* Malo, porque en producción el equipo seguiría siendo responsable de los datos, el almacenamiento y las copias de seguridad.
* Malo, porque aumenta el riesgo operativo frente a un servicio especializado de base de datos.
