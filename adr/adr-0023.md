# automatizar pruebas y despliegues

* Estado: propuesto
* Decidentes: Jaider Sebastián Lucuara Cortés - John Esteban Roldán Marín
* Fecha: 2026-09-22

## Contexto y planteamiento del problema

Publicar nuevas versiones de MyComplex de forma manual puede provocar errores y hacer difícil saber exactamente qué versión fue probada y desplegada. Se necesita un proceso automático que ejecute pruebas, construya la imagen Docker y publique las versiones aprobadas de manera repetible.

## Impulsores de decisión

* Reducir errores humanos durante la publicación de nuevas versiones.
* Ejecutar pruebas automáticamente antes de desplegar cambios.
* Mantener un proceso repetible y registrado.
* Integrarse con el repositorio GitHub, Docker y los servicios de Azure seleccionados.

## Opciones consideradas

* GitHub Actions
* Azure DevOps Pipelines
* Jenkins administrado por el equipo

## Resultado de la decisión

Opción elegida: **"GitHub Actions"**, porque el código de MyComplex ya puede mantenerse en GitHub y esta herramienta permite ejecutar pruebas, construir la imagen Docker, publicarla en el registro y desplegarla en Azure desde el mismo repositorio. Para un equipo pequeño ofrece un proceso sencillo y evita administrar un servidor adicional de automatización.

### Consecuencias positivas

* Las pruebas se pueden ejecutar automáticamente con cada cambio importante.
* Se reduce la cantidad de pasos manuales para publicar una nueva versión.
* Queda un registro de qué cambios y qué versiones fueron desplegados.
* Se integra con Docker y los servicios Azure utilizados por MyComplex.

### Consecuencias negativas

* Los flujos de automatización deberán mantenerse junto con el proyecto.
* Una configuración incorrecta de permisos podría permitir acciones no deseadas.
* El proceso queda parcialmente ligado a GitHub.

## Pros y contras de las opciones

### GitHub Actions

Herramienta de automatización integrada directamente con los repositorios de GitHub.

* Bien, porque mantiene código y automatización en el mismo lugar.
* Bien, porque tiene integraciones maduras con Java, Docker y Azure.
* Bien, porque no requiere mantener un servidor propio.
* Malo, porque genera dependencia de GitHub para el proceso de automatización.

### Azure DevOps Pipelines

Herramienta de Microsoft para construir, probar y desplegar aplicaciones.

* Bien, porque se integra muy bien con Azure.
* Bien, porque ofrece controles avanzados para procesos empresariales.
* Malo, porque introduciría otra plataforma si el código permanece en GitHub.
* Malo, porque aumenta la cantidad de herramientas que un equipo pequeño debe administrar.

### Jenkins administrado por el equipo

Servidor de automatización que debe instalarse y mantenerse directamente.

* Bien, porque es flexible y cuenta con una gran cantidad de extensiones.
* Bien, porque puede adaptarse a muchos entornos diferentes.
* Malo, porque requiere administrar actualizaciones, seguridad y disponibilidad del servidor.
* Malo, porque añade una carga operativa innecesaria para el tamaño actual de MyComplex.
