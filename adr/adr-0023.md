# publicar mycomplex con un dominio y una conexion segura

* Estado: propuesto
* Decidentes: Jaider Sebastián Lucuara Cortés - John Esteban Roldán Marín
* Fecha: 2026-09-22

## Contexto y planteamiento del problema

Los usuarios deben poder ingresar a MyComplex mediante direcciones fáciles de reconocer, como `app.mycomplex.com`, y con una conexión segura mediante HTTPS. Se necesita una alternativa sencilla para administrar los registros del dominio y renovar los certificados sin agregar costos innecesarios ni obligar al equipo a realizar renovaciones manuales.

## Impulsores de decisión

* Utilizar direcciones claras y estables para acceder a MyComplex.
* Proteger la información enviada entre los usuarios y la plataforma mediante HTTPS.
* Evitar costos adicionales por un servicio DNS cuando exista una alternativa gratuita adecuada.
* Evitar que el equipo tenga que renovar certificados manualmente.
* Mantener la configuración sencilla para el tamaño actual del proyecto.
* Ser compatible con Azure Front Door, seleccionado para proteger el tráfico de entrada.

## Opciones consideradas

* Cloudflare DNS gratuito con certificado administrado por Azure Front Door.
* Azure DNS con certificado administrado por Azure Front Door.
* DNS ofrecido por el registrador del dominio con certificado administrado por Azure Front Door.
* Nginx con certificados Let's Encrypt administrados por el equipo.

## Resultado de la decisión

Opción elegida: **"Cloudflare DNS gratuito con certificado administrado por Azure Front Door"**, porque Cloudflare permite administrar los registros DNS sin costo en su plan gratuito y Azure Front Door puede encargarse de emitir y renovar el certificado HTTPS. De esta manera MyComplex evita pagar un servicio DNS adicional y también evita que el equipo tenga que renovar certificados manualmente.

Cloudflare se utilizará únicamente para administrar los registros DNS. El dominio de MyComplex apuntará directamente a Azure Front Door para que el tráfico continúe pasando por la protección definida para la aplicación y para facilitar la renovación automática del certificado.

### Consecuencias positivas

* El servicio DNS puede utilizarse sin costo durante la etapa actual del proyecto.
* Los usuarios podrán acceder mediante un dominio fácil de reconocer.
* La información enviada por Internet estará protegida mediante HTTPS.
* El certificado puede renovarse automáticamente sin intervención del equipo.
* El DNS seguirá siendo independiente del proveedor donde se aloje la aplicación.

### Consecuencias negativas

* Se agrega Cloudflare como un proveedor adicional que debe configurarse.
* El dominio debe comprarse y renovarse por separado; el registro del nombre de dominio no es gratuito.
* Una configuración incorrecta de los registros DNS puede impedir el acceso temporal a la aplicación.
* Cloudflare deberá utilizarse solo como DNS en esta configuración para evitar interferir con el flujo definido en Azure Front Door.

## Pros y contras de las opciones

### Cloudflare DNS gratuito con certificado administrado por Azure Front Door

Cloudflare administra los registros del dominio y Azure Front Door administra el certificado HTTPS.

* Bien, porque Cloudflare ofrece DNS gratuito para el alcance actual del proyecto.
* Bien, porque no se cobra por las consultas DNS en el plan gratuito.
* Bien, porque el certificado puede ser administrado y renovado por Azure Front Door.
* Bien, porque el DNS no queda ligado al mismo proveedor donde se ejecuta MyComplex.
* Malo, porque introduce un proveedor adicional.
* Malo, porque requiere configurar correctamente los registros para que apunten directamente a Azure Front Door.

### Azure DNS con certificado administrado por Azure Front Door

Azure administra tanto los registros DNS como la publicación segura del dominio.

* Bien, porque mantiene la mayor parte de la infraestructura en una misma plataforma.
* Bien, porque se integra directamente con los servicios Azure.
* Malo, porque Azure DNS genera un costo adicional que no aporta un beneficio suficiente para la etapa actual de MyComplex.
* Malo, porque aumenta la dependencia de Azure.

### DNS ofrecido por el registrador del dominio con certificado administrado por Azure Front Door

Se utilizan los servidores DNS incluidos por la empresa donde se compra el dominio.

* Bien, porque algunos registradores incluyen DNS sin costo adicional.
* Bien, porque evita crear otra cuenta si el registrador ofrece una buena administración DNS.
* Malo, porque las funciones y facilidad de uso dependen del registrador elegido.
* Malo, porque la calidad del servicio DNS puede variar entre proveedores.

### Nginx con certificados Let's Encrypt administrados por el equipo

El equipo configura directamente la publicación del dominio y las renovaciones de certificados.

* Bien, porque permite utilizar certificados gratuitos.
* Bien, porque ofrece control completo sobre la configuración.
* Malo, porque el equipo debe mantener el servidor y las renovaciones.
* Malo, porque un error en la renovación puede generar alertas de seguridad o impedir el acceso a la aplicación.
