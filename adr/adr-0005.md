# controlar la concurrencia en operaciones criticas

* Estado: propuesto
* Fecha: 2026-09-08

## Contexto y planteamiento del problema

MyComplex puede recibir solicitudes simultáneas sobre una misma información o recurso, especialmente en funcionalidades como la reserva de zonas comunes. Se debe evitar que operaciones ejecutadas al mismo tiempo generen conflictos, duplicados o información inconsistente en el sistema. ¿Qué estrategia de control de concurrencia resulta más conveniente para garantizar la integridad de las operaciones críticas de MyComplex?

## Impulsores de decisión

* Garantizar la integridad y consistencia de la información.
* Evitar condiciones de carrera en operaciones simultáneas.
* Prevenir reservas duplicadas o incompatibles.
* Mantener un buen rendimiento cuando varios usuarios utilicen el sistema.
* Reducir bloqueos prolongados sobre los recursos de la base de datos.
* Utilizar una solución compatible con la arquitectura y tecnologías previstas para MyComplex.
* Evitar una complejidad innecesaria para el tamaño actual del proyecto.

## Opciones consideradas

* Control de concurrencia pesimista.
* Control de concurrencia optimista.
* Validación de disponibilidad sin un mecanismo explícito de control de concurrencia.

## Resultado de la decisión

Opción elegida: **"Control de concurrencia optimista complementado con restricciones y validaciones en la base de datos para operaciones críticas"**, porque ofrece el mejor equilibrio entre integridad de la información, rendimiento y complejidad para MyComplex.

En MyComplex pueden existir situaciones en las que varios usuarios intenten modificar simultáneamente un mismo registro o utilizar un mismo recurso, como una zona común disponible para reserva. El control de concurrencia optimista permite detectar si la información fue modificada por otra operación antes de confirmar un cambio, evitando sobrescribir modificaciones de manera silenciosa.

Esta alternativa resulta más conveniente para MyComplex que mantener bloqueos prolongados sobre los registros, ya que los conflictos simultáneos no se esperan de manera constante. Además, las operaciones críticas se complementarán con restricciones y validaciones en la base de datos para evitar inconsistencias que no puedan garantizarse únicamente desde la aplicación.

### Consecuencias positivas

* Reduce el riesgo de sobrescribir modificaciones realizadas por otro usuario.
* Evita mantener bloqueos prolongados sobre los registros de la base de datos.
* Mantiene un buen rendimiento cuando existen múltiples usuarios utilizando el sistema.
* Permite detectar conflictos y tratarlos desde la aplicación.
* Es compatible con las tecnologías previstas para el backend de MyComplex.
* Puede complementarse con restricciones de base de datos para proteger operaciones críticas.

### Consecuencias negativas

* Será necesario implementar y manejar correctamente los conflictos de concurrencia.
* Algunos usuarios podrían tener que actualizar la información o repetir una operación cuando ocurra un conflicto.
* El control optimista por sí solo puede no ser suficiente para garantizar determinadas reglas de negocio.
* Será necesario identificar cuáles operaciones requieren controles adicionales en la base de datos.
* La implementación y las pruebas deberán considerar escenarios de operaciones simultáneas.

## Pros y contras de las opciones

### Control de concurrencia pesimista

Consiste en bloquear determinados registros mientras una operación los está utilizando o modificando, evitando que otras operaciones accedan simultáneamente a ellos de la misma manera.

* Bien, porque puede evitar directamente que dos operaciones modifiquen simultáneamente un mismo recurso.
* Bien, porque puede ser útil en escenarios donde los conflictos sobre un mismo registro son frecuentes.
* Malo, porque puede generar esperas innecesarias para los usuarios de MyComplex.
* Malo, porque puede afectar el rendimiento si existen múltiples operaciones sobre los mismos recursos.
* Malo, porque aumenta el riesgo de bloqueos prolongados y posibles `deadlocks` si no se implementa correctamente.

Para MyComplex, esta opción puede resultar excesiva como estrategia general, debido a que mantener bloqueos prolongados puede afectar el rendimiento sin que exista una necesidad constante de este tipo de control.

### Control de concurrencia optimista

Consiste en permitir que las operaciones se ejecuten normalmente y verificar, antes de confirmar una modificación, si otro usuario modificó previamente la misma información.

* Bien, porque evita mantener bloqueos prolongados en la base de datos.
* Bien, porque ofrece un buen rendimiento cuando los conflictos no son frecuentes.
* Bien, porque permite detectar modificaciones simultáneas antes de sobrescribir información.
* Bien, porque puede implementarse utilizando mecanismos de control de versiones compatibles con las tecnologías previstas para MyComplex.
* Malo, porque requiere manejar correctamente los conflictos detectados.
* Malo, porque un usuario puede tener que repetir una operación cuando otro usuario haya modificado previamente la información.

Para MyComplex, esta opción resulta conveniente porque se espera que la mayoría de las operaciones puedan ejecutarse sin conflictos constantes, permitiendo mantener un equilibrio entre rendimiento e integridad.

### Validación de disponibilidad sin un mecanismo explícito de control de concurrencia

Consiste en verificar que un recurso esté disponible antes de realizar una operación, sin implementar mecanismos adicionales para controlar situaciones en las que dos solicitudes ocurran simultáneamente.

* Bien, porque es sencilla de implementar inicialmente.
* Bien, porque requiere poco esfuerzo de desarrollo.
* Malo, porque dos usuarios podrían consultar la disponibilidad del mismo recurso al mismo tiempo.
* Malo, porque ambos usuarios podrían intentar completar la operación antes de que el sistema registre el primer cambio.
* Malo, porque puede generar condiciones de carrera, duplicados o información inconsistente.

Para MyComplex, esta alternativa no es conveniente en operaciones críticas como las reservas, debido a que una validación previa por sí sola no garantiza la integridad de la información cuando existen solicitudes simultáneas.
