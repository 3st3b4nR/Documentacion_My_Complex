# recuperar los datos ante fallos o perdida

* Estado: propuesto
* Decidentes: Jaider Sebastián Lucuara Cortés - John Esteban Roldán Marín
* Fecha: 2026-09-22

## Contexto y planteamiento del problema

MyComplex almacenará información necesaria para la operación de los conjuntos residenciales. Un error humano, un fallo técnico o una corrupción de datos podría causar pérdida de información, por lo que se necesita una estrategia que permita recuperar la base de datos a un estado anterior de manera controlada.

## Impulsores de decisión

* Reducir el riesgo de pérdida permanente de información.
* Poder recuperar la base de datos después de errores o fallos graves.
* Evitar depender de copias hechas manualmente por el equipo.
* Integrar la recuperación con PostgreSQL administrado.

## Opciones consideradas

* Copias automáticas y recuperación a un punto anterior con Azure Database for PostgreSQL
* Copias programadas manualmente mediante `pg_dump`
* Copias manuales realizadas únicamente antes de cambios importantes

## Resultado de la decisión

Opción elegida: **"Copias automáticas y recuperación a un punto anterior con Azure Database for PostgreSQL"**, porque permite que el servicio genere respaldos de forma periódica y ofrece la posibilidad de recuperar la base de datos a un momento anterior dentro del periodo disponible. Esto reduce la dependencia de tareas manuales y brinda una protección más constante para la información de MyComplex.

### Consecuencias positivas

* Las copias de seguridad se realizan de forma automática.
* Se puede recuperar información después de un error o daño en los datos.
* Se reduce el riesgo de olvidar realizar un respaldo manual.
* La estrategia se integra con el servicio de PostgreSQL seleccionado.

### Consecuencias negativas

* La retención de copias y la recuperación pueden generar costos adicionales.
* Se deben definir claramente cuánto tiempo se conservarán los respaldos.
* El equipo deberá realizar pruebas periódicas para comprobar que la recuperación funciona correctamente.

## Pros y contras de las opciones

### Copias automáticas y recuperación a un punto anterior con Azure Database for PostgreSQL

Funcionalidad administrada del servicio de base de datos para crear respaldos y restaurar información.

* Bien, porque las copias se realizan sin depender de una tarea manual del equipo.
* Bien, porque permite recuperar la base a un momento anterior.
* Bien, porque se integra directamente con la base de datos seleccionada.
* Malo, porque la conservación de respaldos puede aumentar los costos.

### Copias programadas manualmente mediante `pg_dump`

El equipo crea tareas que generan archivos de respaldo de PostgreSQL periódicamente.

* Bien, porque ofrece control sobre el formato y el lugar donde se guardan las copias.
* Bien, porque puede utilizarse en diferentes proveedores.
* Malo, porque el equipo debe mantener y supervisar las tareas de respaldo.
* Malo, porque requiere diseñar adicionalmente dónde guardar, proteger y probar esas copias.

### Copias manuales realizadas únicamente antes de cambios importantes

El equipo crea respaldos de forma manual cuando considera que son necesarios.

* Bien, porque tiene un costo y complejidad inicial bajos.
* Bien, porque no requiere configurar automatización.
* Malo, porque deja largos periodos sin protección adecuada.
* Malo, porque depende de que una persona recuerde realizar la copia.
